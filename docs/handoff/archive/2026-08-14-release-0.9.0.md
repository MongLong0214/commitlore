# 0.9.0 — scope, order, and where it stands

Written to be read from the repository rather than from a conversation. Update
it when the state below stops being true.

## What decides whether an issue is in 0.9.0

**Does a user who does not know about this defect install CommitLore, use it,
and get a wrong result?** If yes it blocks the release. If no it waits.

"Or the documentation already promises it" is the second half — a claim we
publish is a claim we owe.

The label is `release:0.9.0`, so the answer is one query rather than a reading
of every open issue:

```sh
gh issue list --label "release:0.9.0"
```

## Deliberately not in 0.9.0

Each of these is real; none of them changes what a user gets.

- **#652** agent session identifiers in this repository's own history — our
  hygiene, not their result
- **#648** the canonical manifest serialising every branch that touches `dist`
  — contributor cost, measured at seven forced rebuilds in one day
- **#649** a test that asserted nothing in ~17% of runs — our confidence
- **#646** guard's keyword weighting — ADR-0020 already states guard is an
  experimental advisory
- **#634** a stale index answers by full scan; the answer stays correct and the
  product reports what it could not read. Honest degradation, not a wrong
  result.
- R2 autocapture (#527, #550, #583, #618, #619, #511, #424) and the research
  and distribution milestones — their own gates

## Release notes must carry two behaviour changes

Both are visible in `doctor` output before anyone reads a changelog.

1. **A timeout is no longer a verdict.** The MCP probe's budget moved from five
   seconds to fifteen, because a *passing* probe on Windows consumed 4478ms of
   the old one, and `initialize-timed-out` now reports *could not verify this
   time* rather than *this registration is broken*. A closed input, an early
   exit or a foreign identity still say unhealthy.
2. **The index binds a cached signature verdict to the keyring that produced
   it.** Signature mode records which keys its verifier could see; a reader
   whose keys differ rebuilds rather than serving a verdict about a keyring
   that is gone.
