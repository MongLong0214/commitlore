# The plan to v1.0.0, in one place

Written because the plan existed in three places and two of them were session
messages that do not survive a compaction. This file is the merge. Where they
disagreed, the owner's execution SSOT wins — it was written against the code;
the other two were written against the issue list.

Dependencies are not anyone's preference. They are stated as facts about the
code, with what establishes them, so a later reader can re-check rather than
re-derive.

---

## Scope, fixed

`Git-native lifecycle-aware decision delivery with verified assisted capture`.

Explicitly **not** v1: deterministic autocapture, every-commit assessment, a
hosted service, a dashboard, a commercial control plane, multi-host
certification, further benchmarks. Do not pull autocapture back in as a
blocker — that decision is made.

Terminal state: open PRs 0, open issues 0, open milestones 0, latest release
`v1.0.0`, main protected with every required check green, repository in
maintenance mode.

## Gates

**Gate 1 — the answer contract.** Merged as #670, with remainder.
**Gate 2 — contract freeze.** Protocol 2.0 Stable, compatibility and deprecation
policy, SECURITY.md, README distinctions, superseding the stale handoffs.
**Gate 3 — release candidate** at an exact SHA.
**Gate 4 — burn-in** on real repositories.
**Gate 5 — GA.**

Rules that hold across all of them: no new features, no new child issues, no
force push, no history rewrite, no branch-protection weakening, no admin bypass.
Every mutation gets a remote read-back. A required check that is failed, missing,
skipped or neutral blocks the merge. Work not actually done is not reported as
done.

## Dependencies

**#671 → #590(b) does not exist. #671 is closed as not-a-defect.**

It was filed on the belief that `bench/report.ts` fails to apply the
registration's row exclusions. It does not fail to — it declines to, and says so
at `bench/report.ts:16-18`:

> **Failed runs stay visible.** The analysis set drops rows that carry no
> measurement, but the unfiltered table and the exclusion counts are printed
> next to it. A run that crashed is never silently absent from a denominator.

So `585 / 584` is the unfiltered table and `580 / 579` is the registered analysis
set. Both correct, answering different questions. Making `report.ts` apply the
exclusions would have destroyed the property that rule exists to guarantee.

**What #590(b) actually needs** is a prose fix, not a regeneration. The README's
running text pairs a numerator from one population with a denominator from the
other:

```
README prose   2.7% (16/585)     numerator from the analysis set,
                                 denominator from the unfiltered table
verdict        2.8% (16/580)     the registered analysis set
generated      585 / 584         unfiltered, correct, labelled as such
```

The generated block was never wrong. Correct the prose to `16/580` (2.8%) and
`109/579` (18.8%) in all four READMEs, then flip
`scripts/check-readme-numbers.mjs` from notice to gate. `findVerdictMismatches`
is already written and already names these two fractions.

The public M5 headline, fixed: registered 1,160 · analyzed 1,159 · excluded by
the registered rule 1 · `commitlore-on` 16/580 = 2.8% · `commitlore-off` 109/579
= 18.8%.

## Traps this repository sets

Each of these cost a cycle today.

- The canonical docker build follows a symlinked `node_modules` and replaces it
  with linux binaries. **Copy, never symlink** — a symlink corrupts the main
  checkout too.
- `vitest -u` writes machine-dependent values straight into snapshots. Read the
  diff before committing one; an absolute path went in this way.
- The JSON shape is pinned in **two** places: `test/query.test.ts` and
  `test/mcp.test.ts`. Changing one is not enough, by design.
- The README checker must write notices to **stdout**;
  `test/readme-numbers.test.ts` asserts stderr is empty so that stderr keeps
  meaning failure.
- Most `ERROR:` lines in a CI log are the stderr of **passing** tests that feed
  `assert-dogfood.mjs` deliberately bad input. Read the exit code and the `FAIL `
  marker, not the loudest lines.
- `Record-Id` needs six characters after `r-`. Five is refused.
- Rebuild the canonical artifact **once**, at the end of a bundle. Every rebuild
  serialises the queue (#648).
