# After v1.0.0 — what is true, and what is left

Written the day v1.0.0 shipped, from remote state rather than memory.

## Shipped

`v1.0.0`, tagged on the merge commit of the version bump, published with notes
whose every figure was checked against its source. The protocol is **2.0
Stable** with a retirement rule: nothing in SPEC §3 is removed in 2.x, and a
record committed today stays readable under any 2.x reader.

The scope is **verified assisted capture**. Deterministic autocapture is
excluded and the product says so — in the README's automatic-vs-not table, and
in `auto status`, whose first line no longer contradicts its third.

## The two issues left

**#660 — a release reaches the CLI wrapper and not the plugin cache.**
Demonstrated by v1.0.0 itself: `install.sh` updated the wrapper to `1.0.0` and
the plugin cache stayed at `0.8.0`. Its closing condition is now a command
rather than a person:

> `commitlore doctor` reports `live MCP runtime identity` with zero unusable
> runtimes.

Fixing it needs sessions to restart, which is outside this product. Deciding
whether it is fixed is not.

**#682 — `hermes install` could not recognise the config it wrote.** Found by
installing v1.0.0 over v0.8.2, which is the only way it could have been found.

## What the day was actually about

Most of the closed issues were not repairs. Fourteen closed because the claim
was narrowed to match the product rather than the product widened to match the
claim, and two closed because they did not reproduce. The repairs were six.

That ratio is the release. A version number is a promise about what is true, and
most of the work was making the promises smaller and checkable rather than
making the product larger.

Three of them are worth naming, because each was a true observation with a false
name:

- The README published `2.7% (16/585)` — a numerator from the registered
  analysis set and a denominator from the unfiltered table beside it. The
  percentages rounded the same, so it survived until something compared the
  fractions.
- `auto status` led with `on` while the two lines beneath it said nothing
  initiates capture. Every line was true; the first one was the wrong half.
- `hermes install` refused an upgrade naming `mcp_servers.commitlore.command`,
  which was correct. The mismatch was a formatting difference in `args`.

## Three defects reached v1.0.0, and none was reachable from the suite

#681, #682 and #686. Each lives where the product meets a machine that already
has state — a config from a previous version, a checkout that is not the
installation, a release that already exists. Section 6c of the release gate is
the response, and it is a human step on purpose.

That is the sharpest thing this release taught, and it is worth more than the
issue count: **the suite starts from nothing every time, which is what makes it
repeatable and what makes it blind.**

## Traps this repository sets

Each cost a cycle today.

- The canonical docker build follows a symlinked `node_modules` and replaces it
  with linux binaries. **Copy, never symlink** — a symlink corrupts the main
  checkout too, and a suite run afterwards reports failures that are not real.
- `vitest -u` writes machine-dependent values into snapshots. Read the diff.
- A negative control that reverts a source file also reverts the fix. Do it on a
  copy, or verify the fix is still there before committing.
- Most `ERROR:` lines in a CI log are the stderr of **passing** tests feeding
  deliberately bad input to a validator. Read the exit code and the `FAIL `
  marker.
- A test that reads the same source the code reads can only agree with itself.
  Pin the failure mode, not the value.
- `git push` printing `branch set up to track` does not mean a commit was
  pushed. Read `git ls-remote` back.
